# Component library format (v0.1)

Goal: a person or an AI can pick a part, read its datasheet numbers, and compute how a circuit built from it
performs: nominal, worst case (min/max), as tables and plots. Everything must be checkable against the datasheet by a
human with the PDF open.

Rules that override convenience:
1. **Every number has a cite.** `DS p.<printed page>, <table or figure title>, <row>`. No cite, no number.
2. **Never invent a value.** If the datasheet gives only typ, store only typ. If it gives only max, store only max.
   Do not fill a missing min/typ/max with a guess, a midpoint, or a value read off a curve. Curve readings are allowed
   only in a separate field `curve = true` and are never used as worst-case bounds.
3. **Store raw datasheet values in the datasheet's printed units.** No derating, no rounding, no unit conversion
   in the TOML. The loader converts to SI.
4. **Simple beats clever.** Plain Python, plain TOML, standard KiCad files. Python stdlib + matplotlib only.

## Directory layout

```
components/<Manufacturer>/<Value>/     Value = orderable part minus reel suffix (INA821IDGK)
  component.toml        part info, pins, parameters (the data)
  calc.py               datasheet equations as plain functions (the math)
  <Value>.kicad_sym     KiCad symbol      (fixed up from vendor, see docs/KICAD.md)
  <Value>.kicad_mod     KiCad footprint   (pads per datasheet land pattern; STEP embedded when available)
  README.md             GENERATED by `python3 -m lib.readme`; never hand-edit
lib/                    loader, units, worst-case engine, report/plot helpers, validator
examples/               worked circuit analyses that use several parts
docs/datasheets/        PDFs (not committed)
docs/vendor/<Value>/    vendor KiCad/STEP downloads (not committed)
```

## component.toml

```toml
[part]
value          = "INA821IDGK"            # directory name
mpn            = "INA821IDGKR"           # orderable, with reel suffix
alternates     = ["INA821IDGKT"]         # same part, other packaging only
manufacturer   = "Texas Instruments"
description    = "Precision instrumentation amplifier, 4.5-36 V"
category       = "instrumentation_amplifier"
package        = "VSSOP-8 (DGK0008A)"
datasheet_url  = "https://www.ti.com/lit/ds/symlink/ina821.pdf"
datasheet_file = "docs/datasheets/ina821.pdf"
datasheet_rev  = "SBOS893D"
datasheet_date = "2020-06"
temp_grade     = "-40 to 125 degC"       # informational; the number lives in a param
kicad_symbol    = "INA821IDGK.kicad_sym"
kicad_footprint = "INA821IDGK.kicad_mod"
step            = "embedded"              # "embedded" | "<file>.step" | "none"

[[pin]]
number   = "1"
name     = "-IN"                          # verbatim from the datasheet; a printed minus or en dash (–) is ASCII "-"
type     = "input"                        # KiCad electrical type (see below)
function = "Negative (inverting) input"   # short, from the datasheet pin table
cite     = "DS p.3, Pin Functions, -IN"

# One table per parameter. Key = snake_case identifier, unique in the file.
[param.vosi_25c]
name       = "Input stage offset voltage"
symbol     = "VOSI"                       # as printed in the datasheet
kind       = "electrical"                 # abs_max | rec_op | electrical | thermal | mechanical
scope      = "25C"                        # "25C" | "full" | "partial" | "na"
typ        = 10
max        = 35                           # omit any of min/typ/max that the DS does not give
unit       = "uV"
conditions = "TA = 25 degC, VS = +/-15 V, RL = 10 kohm"
cite       = "DS p.6, 7.5 Electrical Characteristics, VOSI"
note       = "Specified by characterization (DS note 3)"   # optional
```

### Fields

| Field | Required | Meaning |
|---|---|---|
| `name` | yes | Plain-English parameter name |
| `symbol` | if DS has one | Symbol exactly as printed |
| `kind` | yes | `abs_max`, `rec_op`, `electrical`, `thermal`, `mechanical` |
| `scope` | yes | `25C` = only at 25 °C; `full` = over the grade's full temperature range; `partial` = over only part of the grade's range (say which in `conditions`; do not use for worst case over the full range); also used, with a note saying why, for a rec-op row that applies only under a condition the independent-net check cannot see (a feature in use, a pin wired a certain way, two pins on the same net), so its Zener check is a waivable warning; `na` = anything else (abs max, mechanical, or a single stated temperature such as "at 70 °C", which then goes in `conditions`) |
| `min` / `typ` / `max` | one of these or `text` | Numbers exactly as printed. A `±X` limit is `min = -X, max = X` |
| `text` | if no number | A rating the DS states in words or as a formula ("Continuous", "(P x R)^1/2"). Use only when there is no number |
| `unit` | yes | See units. Use `""` for unitless (gain V/V, ratio) |
| `conditions` | yes | Test conditions as printed; `""` if none |
| `cite` | yes | `DS p.<printed page>, <table/figure title>, <row>` |
| `min_ref` / `max_ref` | no | Name of a pin or rail the min/max is relative to. Example: VCM range `(V-)+2 V to (V+)-2 V` is `min = 2, min_ref = "-VS", max = -2, max_ref = "+VS"` |
| `typ_ref` | no | Like `min_ref`/`max_ref`, for typ: the DS prints "Typ = VS + 11 V" as `typ = 11, typ_ref = "+VS"`. `part.resolve()` returns typ = offset + the rail's typ (a float rail is exact; a rail Param without typ gives typ `None`). The Zener generator ignores typ |
| `tol_pct` | no | `[lo, hi]` printed percentages: the DS prints a typ with "-10 % / +10 %" in the MIN/MAX columns. Store `typ` as printed plus `tol_pct = [-10, 10]`, no `min`/`max`. The loader sets min = typ x (1 + lo/100) and max = typ x (1 + hi/100), sorted so min <= max (also for a negative typ); wca and Zener checks use those. The README shows "-10 %" / "+10 %" in the Min/Max cells |
| `variants` | no | Family directories only: list of variant Values the row applies to; absent = all variants (see "Families and variants") |
| `dielectric` | no | Capacitor series only: the row applies to catalog parts of that dielectric (`"X7R"`); absent = all (see "Capacitor series") |
| `parts` | no | Capacitor series only: list of catalog values (MPN without package letter) the row applies to; absent = all. A row has `dielectric` or `parts`, not both |
| `note` | no | Footnotes, characterization notes, ambiguity |
| `sym` | no | `true` if the DS prints an unsigned magnitude bound for a quantity that can have either sign (TI prints VOS "40 uV" max, meaning ±40 uV). Store `max` (and `typ`) as printed; the loader sets min = -max. Say why in `note` |
| `check_pins` | no | Zener wrapper: list of `[[pin]]` names whose net voltage must stay within this row's min/max (with `min_ref`/`max_ref` resolved to those pins' nets). Voltage rows only. See "Zener wrapper" |
| `check_ambient` | no | Zener wrapper: `true` checks the instance's `ambient` config against this row (degC, min and max required) |
| `unchecked` | no | Reason a rating row is not a Zener check, or why some of its pins are not (`owner: module`, `covered by <key>`). Every `abs_max` and `rec_op` row needs `check_pins`, `check_ambient` or `unchecked` |
| `typ_pm` | no | `true` if the DS prints `±X` in the TYP column; see "Signs and ordering" |
| `curve` | no | `true` if read off a graph. Must name the figure or graph in `cite`. Never a guaranteed bound: a calc function that uses one must say in its docstring that the result is a curve-based estimate |

Signs and ordering:
- Always store `min <= typ <= max` numerically. Some datasheets print negative currents in magnitude order
  (MIN -2, MAX -6): store `min = -6, max = -2` and say so in `note`, quoting the printed columns.
- A printed `±X` limit is `min = -X, max = X`.
- A printed `±X` in the TYP column (gain error typ ±0.025 %) is a spread around zero: store `typ = X` and
  `typ_pm = true`. The loader returns typ = 0 and keeps X as `typ_spread`. Do not use `typ_pm` where ± means two
  directions of a magnitude (short-circuit current ±20 mA source/sink): store the magnitude and explain in `note`.
- A dual-supply range printed `±2.25 V to ±18 V` is stored as the magnitude per rail, with a note.
- Negative quantities stay signed (sourcing currents printed negative stay negative). A calc function that needs a
  magnitude takes `abs()` of its argument and says so in its docstring.
- A rating with no stated reference pin (INA821 supply ±20 V): store as printed and say in `note` how it is applied
  (each pin relative to the part's ground/common). If the DS states the reference anywhere, cite it and set
  `min_ref`/`max_ref`.

If one parameter has rows for 25 °C and full temperature, make two keys: `vosi_25c` and `vosi_full`.

### Units

Write the unit as printed, using ASCII. Per-part values: a datasheet that prints "63.6 g / 1000 pieces" is stored as
the per-part value in a unit that keeps the printed digits (63.6 mg) with the printed wording in `conditions`. A unit is `[prefix]base[suffix]` with prefix `f p n u m k M G`, base
`V A ohm W F H Hz s C J` (C = coulomb for gate charge, J = joule for avalanche energy), and optional suffix `pp` (peak-to-peak), `/rtHz`, `/degC`, `/us`, `/MHz`, `/V` (transconductance). Examples: `V mV uV nV A mA uA nA pA ohm mohm kohm Mohm W mW F uF nF pF H uH Hz kHz
MHz s ms us ns uVpp nV/rtHz fA/rtHz uV/degC V/us uA/MHz mA/V us/V`. Converted: `mm` -> m, `g mg` -> kg, `uV/V mV/V m%` -> fraction, `mdegC` -> degC, `kcycles` -> cycles (10 kcycles -> 10000), `%` -> fraction
(0.5 % -> 0.005, unit `1`), `ppm` -> fraction (35 ppm -> 35e-6, unit `1`), `ppm/degC` -> 1/degC (unit `1/degC`), `ppm/V` -> 1/V (unit `1/V`). `/us` -> `/s` (2.5 V/us -> 2.5e6 V/s). `/MHz` -> `/Hz` (23.4 uA/MHz -> 2.34e-11 A/Hz). `uV/V` and `mV/V` stay fractions, never `/V` transconductance.
Unscaled: `degC degC/W dB bits LSB cycles years` and `""`. So every value a calc function receives is SI or a plain fraction; README
tables still show the printed units. The loader rejects any unit it does not know.

### Pin types (KiCad)
`input output bidirectional tri_state passive free unspecified power_in power_out open_collector open_emitter no_connect`.
Choose from the datasheet's pin function text, not from the vendor symbol. Pins for external components (gain resistor,
compensation) are `passive`. Exposed pads appear as a pin when the datasheet says to connect them.

## Families and variants

One directory can hold several orderable Values that share a datasheet (LTC4364HMS-1, LTC4364IMS-1). The family
directory is an ordinary component directory (`component.toml`, `calc.py`, KiCad files) plus `variants.toml`; each
variant lists only what differs.

```toml
# components/AnalogDevices/LTC4364MS/variants.toml
[variant."LTC4364HMS-1"]
mpn        = "LTC4364HMS-1#TRPBF"        # any [part] key may be overridden here
alternates = ["LTC4364HMS-1#PBF"]
temp_grade = "-40 to 125 degC"

[variant."LTC4364HMS-1".param.ta_grade]  # replaces the shared row of that key, or adds a row (same schema)
name = "..."                              # ... every field of a normal row
```
- Every variant sets its own `mpn`, `alternates` (may be `[]`) and `temp_grade` (lib.check errors otherwise); the shared
  `[part]` should not carry them.
- In the family `component.toml`, `[part] value` is the family name (= directory name, `LTC4364MS`); each variant's
  Value is its table key in `variants.toml`.
- A shared row may carry `variants = ["LTC4364HMS-1", "LTC4364IMS-1"]`: it applies only to those variants.
- Merged data for a variant: shared `[part]` overridden by the variant's keys (value = the variant); shared rows that
  apply to it, in file order; then each `[variant.X.param.key]` replaces the shared row in place or is appended.
- `load("AnalogDevices/LTC4364MS", variant="LTC4364HMS-1")` returns a normal `Part` for that variant (same calc
  module). `load("AnalogDevices/LTC4364HMS-1")`, a variant Value that is not a directory, scans
  `components/<Mfr>/*/variants.toml` for it. `load()` of a family without `variant=` raises an error listing the
  variants. `Part.variant` is the variant Value (None for a plain part); `Part.family_path` the family directory.
- `lib.check` validates the shared file once (pins vs symbol, footprint, calc) and, for every variant, its required
  `[part]` fields, its override rows, and that every `INPUTS` key resolves in the variant's merged params (errors
  read `variant <Value>: ...`). A `variants` entry naming an unknown variant is an error.
- `lib.readme` writes one README per family: a Variants table (Value, mpn, alternates, temp_grade, and any other
  `[part]` key some variant overrides), the shared tables (restricted rows show "Variants: X, Y" in Conditions), and a
  "Variant-specific parameters" section per variant with overrides.
- `lib.zen` writes one wrapper per variant, `<Variant>.zen`, in the family directory with one `pcb.toml`;
  `pcb build <dir>` builds every entrypoint. The wrapper uses the variant's merged `[part]` and params.

## Series of numbered rows

Keys `<prefix>_<n>` (decimal n, for example `vovc_thr_0` ... `vovc_thr_15`) form a series:
`part.series("vovc_thr")` returns `{0: Param, 1: Param, ...}` sorted by n (numeric, so 2 before 16). `lib.check`
errors when a key ends in `_<digits>` and its `symbol` also does, but the numbers differ ("key suffix 10 != symbol
suffix 16").

## Series components (the value is a design input)

A passive whose value the designer chooses (a resistor series: one directory per package, ERJ-3EKF 0603) is a
series component. (A capacitor series, whose values come from a catalog file, is the next section.) It is an ordinary
component directory plus these `[part]` keys:

```toml
[part]
value          = "ERJ-3EKF"              # directory name; no `mpn` key: calc.mpn(value) gives it
series         = "resistor"              # marks a series component: "resistor" (here) or "capacitor" (next section)
value_param    = "res_range"             # param row: allowed resistance range, min and max, unit ohm
e_series       = ["E24", "E96"]          # allowed values: these IEC 60063 series inside the range
series_power   = "p70"                   # param row: power rating at 70 degC (W, max)
series_vlimit  = "v_limit"               # param row: limiting element voltage (V, max)
series_tol     = "tol"                   # param row: tolerance (%, min and max, e.g. -1 / 1)
series_eseries_min = { E96 = 100 }       # optional: lowest value (ohm) taken from one E-series (here E96)
```

Optional keys, each described below: `series_vlimit` may be absent, `series_tolerances` replaces `series_tol`,
`series_tcr` selects a TCR row per value, `series_pins` names the two current terminals of a 4-terminal part.

- `calc.py` must define `mpn(value)` (value in ohm, returns the orderable MPN text; `mpn(value, tol_code)` for a
  series with tolerance options). It is the single source of the part number: `[part] mpn` must be absent. The README
  gives three example values.
- The allowed values are every `E24` / `E96` mantissa (literal lists in `lib/series.py`, 24 and 96 values per decade)
  times a power of ten that falls in the `value_param` range, sorted and unique (E24 has values E96 lacks, for
  example 2.7). Each is the float nearest its printed decimal: 2.61 x 10^3 is `2610.0`, the same float `2.61e3` gives.
- `series_eseries_min` (optional, keys from `e_series`, positive ohm) drops that E-series' values below its minimum
  (use it where the catalog prints no part-number code for them); a value that another listed series contains stays
  allowed (E24 47 ohm with `E96 = 100`; E96 47.5 ohm is out). `lib.check`, `part.values()` and the wrapper's
  `value_allowed` all use the reduced set.
- **Decade value set.** `e_series = ["VISHAY-DECADE"]` allows every two-significant-digit value 10..99 per decade
  (mantissas 1.0 ... 9.9: 90 values per decade; `lib.series.DECADE`), from Vishay Dale "Standard resistance decade
  values", document 30117, rev 04-Oct-06 (titled "WSL Type Resistors": "Resistance values must be within the
  resistance range listed on the most current datasheet"). It combines with E24/E96 in one list like any other name.
- **No limiting element voltage.** `series_vlimit` is optional. Without it the rated voltage is `sqrt(P70 x R)` only
  (`lib.series.rated_voltage(r, p70)`; the wrapper compares squares and has no `vlim` argument; the README says the
  datasheet prints none).
- **Tolerance options.** Instead of one `series_tol` row, a series may list several orderable tolerances, each with its
  own resistance range (a datasheet that prints a range per tolerance column):

  ```toml
  series_tolerances = { B = { tol = "tol_b", range = "r_range_b" }, D = { tol = "tol_d", range = "r_range_d" } }
  ```

  The key is the tolerance code as printed in the part number (letters/digits). `tol` names a param row (%, min and
  max, like `series_tol`), `range` names a param row (ohm, min and max) holding that option's range as printed, so every
  number keeps its row, unit and cite. `series_tol` and `series_tolerances` are exclusive. `value_param` stays the
  directory's range; each option's range is **clipped** to it (`max(low) .. min(high)`), so one datasheet table splits
  over several directories (`WSK2512-LOW`, `WSK2512`) without editing the printed rows. An option with no value left
  after clipping is ERROR (leave it out of that directory). The allowed set is the sorted list of
  `(value, tolerance code)` pairs; a value is orderable with every code whose clipped range holds it.
- **TCR by range.** `series_tcr = [{ tcr = "tcr_a", range = "tcr_a_range" }, ...]` pairs each TCR row (ppm/degC, min
  and max) with a range row (ohm) for datasheets that print a TCR per resistance range. Every allowed value must fall
  in exactly one range (ERROR for none or several). `part.tcr(value)` returns the Param of that row (a fraction per
  degC), for `wca(calc.resistance_worst, r0=value, tol=part.tolerance(code), tcr=part.tcr(value), ...)`. `INPUTS` cannot
  map the TCR argument when there are several rows (the row depends on the value); with a single row it may map it as
  usual. The rows named by `series_tolerances` and `series_tcr` need no `check_pins` / `unchecked`.
- **Four-terminal parts.** A series has exactly 2 pins unless `series_pins = ["I1", "I2"]` names two different `[[pin]]`
  names (the current terminals): the wrapper's `rated_voltage` check is taken between those nets (default: pins `1`
  and `2`). The other pins (Kelvin sense) are ordinary pass-through nets.
- `lib.check` (series) ERRORs on: a missing `[part]` key or an unknown row key, `mpn` present, a series that does not
  have exactly 2 pins (and no valid `series_pins`), an unknown E-series name, a range or tolerance row without min/max
  (and ohm / % units), a malformed `series_tolerances` / `series_tcr` table, both `series_tol` and `series_tolerances`
  (or neither), an option with no value after clipping, a value with no or several TCR rows, missing `calc.mpn`, and,
  over every allowed (value, code) pair, `calc.mpn` raising or two pairs giving the same MPN. The rows the series reads
  need no `check_pins` / `unchecked`. A series cannot be a family.
- `part.values(tol=None)` returns the sorted allowed values (ohm); with tolerance options, `tol` = a code gives that
  code's values and `None` the values any code allows. `part.pairs()` returns the sorted `(value, code)` list
  (`code` is `None` without options), `part.tolerances()` the codes, `part.tolerance(code)` the tolerance Param
  (fraction). `part.mpn(value, tol=None)` returns `calc.mpn(value)` (or `calc.mpn(value, code)`) for an allowed value;
  `tol` may be left out only when exactly one code allows the value, otherwise `ValueError` "ambiguous: ... pass tol".
  `part.series_value(value, tol=None)` returns a `Param` with typ = value and min/max =
  value x (1 + tol.min), value x (1 + tol.max), in ohm (the row of the code), ready for `wca`:
  `rg = erj.series_value(2.61e3)`. `mpn` and `series_value` raise `ValueError` for a value (or value/code pair) that is
  not allowed or a code that is not an option.
- Example, Vishay WSK2512 (`components/Vishay/WSK2512`, 0.005 to 0.2 ohm, decade values, B/D/F; and `WSK2512-LOW`,
  0.0005 to 0.0049 ohm, D/F): the datasheet prints one table for the whole model, split into two directories where the
  solder pad dimensions change. MPN = `WSK2512` + 5-character value code + tolerance code + `EA`: value code
  `R0250` (0.025 ohm: `R` is the decimal point, four digits of ohm), `5L000` (0.005 ohm: below 0.01 ohm the value is
  in mohm with `L`), `L5000` (0.0005 ohm, inferred: no printed sub-1 mohm example); `0.025 D -> WSK2512R0250DEA`.
  The single part `WSK2512R0250D` stays a separate directory and is also reachable as `WSK2512` 0.025 ohm code D.
- `lib.readme` adds a "Series" section: value range, E-series, tolerance, MPN rule with three example values,
  the rated-voltage formula and a table of rated voltage at the decade values (10 ohm ... 1 Mohm) inside the range,
  "computed from" the power and voltage-limit rows.
- Zener: see "Zener wrapper", "Series wrapper".

## Capacitor series (the part is picked from a catalog)

A capacitor series is a directory for one package whose orderable values are the rows of a committed catalog file.
Murata GCM MLCCs: one directory per Murata size+thickness code (`GCM155`, `GCM188`, `GCM21B`, ...), each with one
symbol, footprint and STEP (the height differs per thickness code), holding every C0G and X7R value. It is an ordinary
component directory plus `catalog.csv` and these `[part]` keys (no `mpn`, no `variants.toml`, exactly 2 pins):

```toml
[part]
value              = "GCM155"            # directory name
series             = "capacitor"
catalog            = "catalog.csv"       # file in this directory
tc_param           = { X7R = "tc_x7r" }  # dielectric -> param row with its temperature characteristic
package_default    = "D"                 # package letter appended to the catalog value: MPN = value + letter
package_alternates = ["W", "J", "V"]     # other letters: the same part in other packaging
```

**catalog.csv** (UTF-8, header row, one row per orderable value; comma separated, quote cells that contain a comma):

| Column | Meaning |
|---|---|
| `value` | MPN without the package letter (`GCM155R71H104KE02`); unique in the file |
| `dielectric` | name as printed by the source (`X7R`, `C0G`) |
| `capacitance` | as printed (`0.1μF`, `6,800pF`, `1.5pF`); units pF, nF, uF (Greek mu or u) |
| `tolerance` | as printed, symmetric (`±10%`, `±0.25pF`); an absolute pF tolerance is divided by C where a fraction is needed |
| `rated_voltage` | as printed (`50Vdc`, `1,000Vdc`) |
| `thickness` | as printed (`0.5mm ±0.05mm`); informational |
| `source` | the cite of the row |

- **The export is the source.** A manufacturer product-list export is a cited source for per-part values. The cite is
  `Murata product list export <file name>, row <part number>` (the part number exactly as the export prints it, with
  the `#` package placeholder). It is not a datasheet table and says so in every Param `note`; per-dielectric and
  per-size rows still cite the reference sheet (`DS p.`).
- **Generating the catalog.** `python3 -m lib.catalog murata-gcm <vendor csv> <component dir> [--dielectrics X7R,C0G]`
  keeps the export rows whose part number carries the directory's size+thickness code (`GCM155` -> `155`) and whose
  `Temperature characteristics` column is an allowed dielectric (default: the keys of `[part] tc_param`, so a dielectric
  with no temperature-characteristic row is never written), In Production only, and writes `catalog.csv` sorted by
  value. Before writing, every kept row is decoded from its part number and compared with the export's own columns:
  size (length and width), thickness code, dielectric code (`5C` = C0G, `R7` = X7R), rated-voltage code (`1H` = 50 V,
  `2A` = 100 V, ...), the 3-digit capacitance code (two digits and a power of ten in pF; `R` is the decimal point:
  `1R5` = 1.5 pF), the tolerance letter, and the operating temperature (-55 to 125 degC, the range of the shared
  `op_temp_*` rows). Any mismatch, a part number of another form or a repeated part number is an error: the row is not
  written and the command exits 1.
- **The decode tables are a cross-check only ("Not a DS rule").** The Murata reference sheets decode just their own
  example part number (DS p.2). Only `15`/`5`, `18`/`8`, `R7`, `1H`, `104`, `K` and the package letters are printed there;
  the other codes come from Murata's published part-number system and are consistent with every row of the export
  (one printed value per code). A row passing the decode proves the export agrees with itself and with the tables,
  not that the tables are Murata's rules. The tables live in `lib/catalog.py`, each with its source.
- **Restricting rows.** In a capacitor series a param row may carry `dielectric = "X7R"` (applies to every catalog part
  of that dielectric: the temperature characteristic, shared test limits) or `parts = ["GCM155R71H104KE02"]` (applies to
  those catalog values only: per-part rows from a reference sheet, such as thickness T, IR limits, stress-test limits).
  Rows with neither apply to every part. Row keys are unique, so a dielectric-specific quantity has one key per
  dielectric (`tc_x7r`, `tc_c0g`).
- **Loading.** `load(dir)` returns a Part holding only the unrestricted rows (`part.hidden` maps the other keys to
  their restriction; `part.param("tc_x7r")` then says which restriction hides it). `part.catalog()` returns the
  `lib.capacitor.CatalogRow` list, `part.dielectrics()` the dielectrics in it.
- **Selecting a part.** `sel = part.select(capacitance, rated_voltage, dielectric, tolerance=None)`; capacitance in F
  and rated voltage in V (or printed text, `"0.1uF"`, `"50Vdc"`), dielectric as in the catalog, tolerance as printed
  (`"+/-10%"` or `"±10%"`) and only needed when the catalog lists several for that value. It returns a `Selection`
  with `value`, `mpn` (value + `package_default`), `alternates` (value + each `package_alternates`), `dielectric`,
  `tolerance`, `thickness`, `capacitance` (Param, F: typ = printed value, min/max from the tolerance),
  `rated_voltage` (Param, V: min = -rating, max = rating, non-polarized) and `part`, a Part of the rows that apply
  to this part (dielectric rows of its dielectric, `parts` rows naming its value) plus the selection keys
  `capacitance`, `tolerance` (fraction), `rated_v` and `tc` (the row `tc_param` names for its dielectric, an alias).
  No match raises `ValueError` ("no catalog part for ...", with the voltages or tolerances that do exist); several
  matches (two tolerances and none given; two values with the same tolerance) raise `ValueError` "ambiguous: ..."
  listing the values. Capacitance and rated voltage match to 1e-9 relative.
- **calc.** Two functions, one per temperature-characteristic kind, so a coefficient can never be read as a fraction.
  `capacitance_worst_pct(c0, tol, tc)` is `C0 x (1 + tol) x (1 + tc)` for percent-change classes (X7R: `tc` a fraction,
  -15 to 15 % over the whole range). `capacitance_worst_ppm(c0, tol, tc, dt)` is `C0 x (1 + tol) x (1 + tc x dt)` for
  ppm classes (C0G: `tc` in 1/degC, 0 +/-30 ppm/degC); `dt` (T - 25 degC) is required, and `ValueError` is raised for
  `dt` below 0 or above 100, because the coefficient is printed for 25 to 125 degC only (below 25 degC the Table A drift
  rows apply, and their docstring says so). Each raises `ValueError` if `tc` has the other kind's magnitude. Each has
  its own `INPUTS` (`c0` -> `capacitance.typ`, `tol` -> `tolerance`, `tc` -> `tc`, the dielectric's row, never
  hard-coded) and its own `EXAMPLES` from printed numbers. Neither includes DC-bias or aging capacitance loss (the
  reference sheets print no number; for X7R these can dominate), and the docstrings say so:
  `wca(sel.part.calc.capacitance_worst_pct, **sel.part.inputs("capacitance_worst_pct"))`, or for C0G
  `wca(sel.part.calc.capacitance_worst_ppm, dt=Param(min=0, max=100), **sel.part.inputs("capacitance_worst_ppm"))`.
  The tolerance and tc rows are bound-only, so the result has no typ unless the caller states one.
- **Re-decoding the catalog.** `[part] catalog_decoder = "murata-gcm"` makes `lib.check` decode every committed row again
  with the offline half of the `lib.catalog` decode (`value + "#"` against the part-number form, then dielectric, rated
  voltage, capacitance code, tolerance letter and thickness code against the row's columns, and the size+thickness
  code against the directory name; length, width and operating temperature exist only in the export and are skipped).
  A hand edit of a column is an ERROR. Same tables as the generator, same "Not a DS rule" status.
- **Suffix convention.** A row key ending in `_c0g` / `_x7r` (the dielectric name, lower case) is expected to be about
  that dielectric: `lib.check` WARNs when such a `parts` row names a part of the other dielectric, or such a
  `dielectric` row names another one.
- `lib.check` (capacitor series) ERRORs on: a missing `[part]` key, `mpn` present, a series that does not have exactly
  2 pins, package letters that are not distinct single capital letters, an unreadable catalog (wrong columns, empty or
  unparseable cells, a repeated `value`; every problem is listed), a catalog dielectric with no `tc_param` entry (such
  parts cannot be listed: add the temperature-characteristic row from that dielectric's reference sheet first), a
  `tc_param` row that is missing, has another `dielectric` or lacks min, max and unit % or ppm/degC, a catalog
  dielectric without exactly one `check_ambient` row (unrestricted or restricted to it), a row with both `dielectric`
  and `parts`, a `dielectric` not in the catalog, a `parts` entry that is not a catalog value, a `check_ambient` or
  `check_pins` row restricted to parts, and a row key that is reserved for the selection (`capacitance`, `tolerance`,
  `rated_v`, `tc`). `INPUTS` may name those four keys. Rating rows still need `check_pins`, `check_ambient` or `unchecked`;
  in a capacitor series only `check_ambient` (per dielectric) and `unchecked` are possible.
- `lib.readme` adds a "Series" section (catalog count, MPN rule, selection, wrapper, a table per dielectric) and shows
  "Applies to: dielectric X7R." / "Applies to: parts ..." in the Conditions of restricted rows.
- Zener: see "Capacitor wrapper".

## calc.py

Datasheet equations, one function per equation. Rules:

- Arguments and return values are plain floats in SI units (V, A, ohm, W, s, Hz), temperatures in °C.
- The docstring states: the equation as text, the cite, and units of every argument and the return value.
- No imports beyond `math`. No access to the TOML. Parameters are passed in as arguments so the worst-case engine
  can sweep them.
- `INPUTS` maps each function's arguments to the `component.toml` param key that supplies them, so nobody has to
  guess which of 80 rows to use. Arguments that are design choices (resistor values, load current) are not listed.
  A value is `"key"` (pass the whole Param; wca sweeps its min/max) or `"key.min"`, `"key.typ"`, `"key.max"`
  (pass that one number, e.g. `"p70.max"` for a rating, `"vcc_op.min"` for a minimum supply). `lib.check`
  verifies every key and field exists, the README prints the map, and `part.inputs("fn")` returns the arguments.
- A `sym = true` row with a printed typ is centred like `typ_pm`: typ = 0, printed typ kept as `typ_spread`.
- Equations not printed in the datasheet but needed to use it correctly (a pin bias current through a divider's
  Thevenin resistance) are allowed only if the docstring starts with `Not a DS equation:` and gives the derivation. An optional
  argument that extends a DS equation (default reproduces the DS equation exactly) may instead carry a line
  `With <arg> != 0 this is Not a DS equation: ...` with the derivation.
- Functions that fit a typical curve end in `_typ` and must not be used as worst-case bounds.
- `EXAMPLES` lists datasheet worked examples or table values that the function must reproduce. These are run by the
  validator. Prefer numbers the datasheet itself prints (gain table, design example).

```python
def gain(rg):
    """G = 1 + 49.4 kohm / RG.  DS p.20, 8.3.1 Gain-Setting, Equation 1.
    rg: gain resistor, ohm.  Returns: gain, V/V."""
    return 1 + 49.4e3 / rg

EXAMPLES = [
    # (function, kwargs, expected, tolerance, cite)
    # tolerance is relative (1e-3 = 0.1 %), except when expected == 0, where it is absolute.
    ("gain", {"rg": 5.49e3}, 9.998, 1e-3, "DS p.20, Table 8-1, G = 10 row"),
]

INPUTS = {
    # function: {argument: param key}
    "vos_rti": {"vosi": "vosi_full", "voso": "vos_o_full"},
}
```
A tolerance looser than 1e-3 needs a comment saying why (the DS rounded to a standard value, for example).

## Temperature and combined errors (the one recipe)
1. If the DS has a full-temperature row (`scope = "full"`), use it: it already covers the whole grade range.
2. Otherwise use the 25 °C row plus drift: `X(T) = X25 + drift * (T - 25)`, with `T` an explicit wca input
   (`Param(min=-40, max=125)`) and `drift` the drift param. Never extrapolate a typ-only drift as a bound.
3. Independent error terms (tolerance, TCR x dT, aging test limit) are separate wca inputs to one function, e.g.
   `R = R0 * (1 + tol) * (1 + tcr * (T - 25))`. Corners then combine them worst case. Each part's `calc.py` should
   provide such a combined function for its main quantity.

## Zener wrapper (generated)

Two layers, one source of truth:
- **TOML + Python** (`component.toml`, `calc.py`) hold every number and equation. Analysis, tables and plots are
  done in Python. This is what a human verifies against the datasheet.
- **Zener** (`<Value>.zen` + empty `pcb.toml`, generated by `python3 -m lib.zen`) is for circuit capture: typed
  pins (`io()`), the KiCad symbol and footprint, part info, and DC checks on the voltages each instance declares.
  Never hand-edit it; change `component.toml` and regenerate. Zener modules (hierarchical circuits) instantiate
  these wrappers with `Module("<path>/<Value>.zen")`.

What the generator emits, so a reviewer can predict the file from the TOML:
- One `io()` per connected `[[pin]]`, named from the pin name (`+IN` -> `IN_P`, `-VS` -> `VS_N`, `V+` -> `V_P`).
  Ground-named pins (`GND AGND DGND PGND SGND VSS VSSA`) are `io(Ground)`; every other pin is `io(Net)`. `power_in`
  and `power_out` pins are cast to `Power(net, voltage=net.voltage)` at the component, so a negative rail or GND can drive them.
  `no_connect` pins are omitted (auto NotConnected). Same-name pins (two GND pins, an exposed pad named GND) are
  one node: one `io()` and one `pins={}` entry.
- `derate` config (default 1.0, must be in (0, 1]), `ambient` config when any row has `check_ambient`, and
  `waive_<key>` config for every warning-level check.
- One check per `check_pins` entry, named `<key>_<IO>`: worst case `v.min >= min + min_ref.max` and
  `v.max <= max + max_ref.min` (no ref = absolute volts). `abs_max` limits are multiplied by `derate` on the side
  away from zero. Severity: `abs_max`/`rec_op`/other rows with scope `full`/`na` are errors; scope `25C`/`partial`
  are warnings, waivable with `waive_<key>` (a non-empty rationale with a cite drops it to advice; errors cannot be
  waived).
- One check per `check_ambient` row, named `<key>_ambient`, against the `ambient` config.
- A checked net with no declared voltage is `UNVERIFIED` (warning, fails `-Dwarnings`); when the wrapper is built
  alone it is advice, so `pcb build <dir>` stays green.
- Every `abs_max`/`rec_op` row without a check is listed as `# UNCHECKED: <key>: <name> (<cite>); <reason>`.
- Checks are DC steady state only (stated in the wrapper docstring).

### Series wrapper

A resistor series component (see "Series components") gets one wrapper, `<Value>.zen`. It differs from the above as follows:
- `value = config(Resistance, ...)`: required, no default (an instance without it fails to build).
- With tolerance options, `tolerance = config(str, default="")`, the code as printed (`D`). It may stay empty only when
  exactly one code allows the value; otherwise `value_allowed` fails and lists the codes. `_MPN` is keyed by
  `(micro-ohm integer, code)`, `_CODES` lists the codes per value, and an unorderable pair gets the sentinel MPN
  `UNORDERABLE` (as in the capacitor wrapper), never a real part number. `value_allowed` checks the pair is a key of
  `_MPN` and its message names every code's clipped range.
- Pins `"1"` and `"2"` become `P1` and `P2` (a purely numeric pin name gets a `P` prefix: `io_name("1") = "P1"`).
  With `series_pins` the voltage across the part is taken between those two pins' nets (`I1`, `I2`).
- `_MPN = {<micro-ohm integer>: "<MPN>", ...}`, generated from `calc.mpn` over every allowed value, and
  `Part(mpn=_MPN_STR, ...)` with `_MPN_STR = _MPN[int(value x 1e6 + 0.5)]`. Keys are integers because float text differs
  between Python and Zener (`1e+06`). Resistance `.value` is a float in ohm (confirmed with a scratch build).
- Check `value_allowed` (error): the configured value is one of the table's keys. It is a check, not an `error()` call,
  because Zener evaluates the module once with a placeholder value of 0 when it is loaded; standalone it is advice.
- Check `rated_voltage` (error, through `_limit`, so an unset net is UNVERIFIED): the worst-case voltage across the
  part, max(P1.max - P2.min, P2.max - P1.min), is at most `derate x min(sqrt(P x R), Vlimit)`, with P from
  `series_power`, Vlimit from `series_vlimit` (their `max`) and R the configured value. Zener has no sqrt, so the
  generated code compares squares. Both rows are generated literals, like every other limit. Without `series_vlimit`
  the limit is `derate x sqrt(P x R)`. The voltage is the declared `v_across` when it is set (below); otherwise the
  net-range expression above.
- Optional config `v_across = config(Voltage, optional=True)`: the declared worst-case voltage across the part, a
  point value or a range, signed or not (the check uses the magnitude, max(|min|, |max|)). The module supplies it from
  its own analysis, for example I_max x worst-case R for a current shunt, or the worst-case drop for a termination
  between two logic nets. It replaces the independent net ranges in `rated_voltage`, so the two nets may stay
  undeclared without an UNVERIFIED for that check. When unset, `rated_voltage` is unchanged. The module owns the
  number and must justify it in a comment at the instance (design analysis; it is not a datasheet value and is not
  in component.toml). The check severity is unchanged: an error, not waivable, and `derate` still shrinks the limit.
- Power derating above 70 degC is a curve (`calc.rated_power`) and is not checked in Zener; the wrapper lists it as
  `# UNCHECKED ... owner: module`. The four series rows are not listed as UNCHECKED (the series check reads them).
- The ambient check comes from the normal `check_ambient` row.

### Capacitor wrapper

A capacitor series (see "Capacitor series") gets one wrapper, `<Value>.zen` (`GCM155.zen`). It differs from the above as
follows:
- Pins `"1"` and `"2"` become `P1` and `P2`, as in the resistor wrapper.
- Required configs: `value = config(Capacitance)`, `rated_v = config(Voltage)` (the rated DC voltage that selects the
  catalog part, `50V`) and `dielectric = config(str)` (as printed in the catalog, `X7R`). Optional `tolerance =
  config(str, default="")`, ASCII as printed (`+/-10%`), needed only when the catalog lists several for that value.
- `_VALUE = {(dielectric, femtofarad, millivolt, tolerance): "<catalog value>", ...}`, generated from `catalog.csv`
  (one row per orderable value, with a trailing comment of the printed values; an unorderable combination gets the sentinel MPN `UNORDERABLE`, never a real part number), and `_TOLS`, the tolerances listed for
  each (dielectric, femtofarad, millivolt). Keys are integers (`int(C x 1e15 + 0.5)`, `int(V x 1e3 + 0.5)`; the same
  arithmetic in `lib.capacitor.zen_key`) because float text differs between Python and Zener. The wrapper adds the
  package letter: `Part(mpn=_MPN_STR)` with `_MPN_STR = <value> + package_default`, and the alternates property is
  `<value> + each package_alternates` (empty when unorderable). Tuple dict keys, a `Voltage` config and `.value` floats were confirmed with a scratch
  build (pcb 0.4.102). Two catalog values with the same key are a generator problem.
- Check `part_orderable` (error; advice when the wrapper is built alone): the configured combination is a key of
  `_VALUE`. The message names the tolerances the catalog lists for it. A check, not an `error()` call, because Zener
  loads the module once with placeholder configs.
- Check `rated_voltage` (error, through `_limit`, so an unset net is UNVERIFIED): max(P1.max - P2.min, P2.max - P1.min)
  is at most `derate x rated_v` (non-polarized, either polarity). `derate` applies, as for the resistor series.
- Check `ambient_range` (error): the `ambient` config inside the `check_ambient` row of the configured dielectric
  (`_AMBIENT = {dielectric: (lo, hi)}`, one `check_ambient` row per dielectric, kelvin). An ambient row must be
  error severity (not 25C or partial).
- Rows restricted to parts, and rating rows restricted to a dielectric without a check, are listed as
  `# UNCHECKED: <key> [parts ...]: ...; <reason>`. DC-bias capacitance loss, aging and AC stress are listed as unchecked
  (owner: module). No `check_pins` in a capacitor series: the rated voltage comes from the catalog.
- The generated module grows with the catalog: about 140 rows is 23 kB (GCM155). A catalog of hundreds of rows builds in
  well under a second.

Choosing check rows: inputs and supplies the circuit sets (supply pins, signal inputs, pull-up rails, divider
inputs) get `check_pins`. Pins the part drives or whose voltage is set by external parts (outputs, gate drives,
timer and compensation nodes, MOSFET source) are `unchecked` with `owner: module`. Temperature ranges of the grade
get `check_ambient`; a looser row covered by a stricter checked one is `unchecked = "covered by <key>"`.
Storage, solder, ESD rows are `unchecked = "owner: assembly"`.

Tests: `tests/zen/<Value>_harness.zen` instantiates the wrapper with nominal passing voltages (each commented);
`tests/test_zen.py` lists cases (nominal pass, each check failing at its severity, a waiver, an unset net) and
checks the committed wrapper equals fresh generator output.

## Using a part (lib API)

```python
from lib import load, Param, wca, table, plot_band

ina = load("TexasInstruments/INA821IDGK")
ina.param("vosi_full")             # Param(min=None, typ=None, max=80e-6, unit='V', cite=...)
rg  = Param.tol(5.49e3, 0.001, "ohm")       # 5.49 kohm +/-0.1 %
g   = wca(ina.calc.gain, rg=rg)  # Param(min=..., typ=..., max=...)
print(table([("Gain", g, "")]))
```

A resistor series component (`[part] series = "resistor"`) also gives `part.values()`, `part.mpn(value)` and
`part.series_value(value)` (with tolerance options also `part.pairs()`, `part.tolerance(code)`, `part.tcr(value)`; see
"Series components"): `wca(fn, r=load("Panasonic/ERJ-3EKF").series_value(2.61e3))`.
A capacitor series gives `part.catalog()` and `part.select(capacitance, rated_voltage, dielectric, tolerance=None)`
(see "Capacitor series"): `sel = load("Murata/GCM155").select(0.1e-6, 50, "X7R", "+/-10%")`, `sel.mpn`, and
`wca(sel.part.calc.capacitance_worst_pct, **sel.part.inputs("capacitance_worst_pct"))` (X7R; `capacitance_worst_ppm` for C0G).

Worst-case method (`wca`), stated so a human can check it by hand:
1. typ = function evaluated with every input at its typ value. If any input has no typ, result typ is `None`.
2. min/max = lowest and highest result over every combination of input min/max values (all 2^n corners).
   Any input with no min or max is a hard error, unless the caller supplies the missing bound explicitly.
3. Corners are exact for functions that are monotonic in each input over the range. For other functions, pass
   `samples=N` to also evaluate N evenly spaced interior points per input.

## Validation

`python3 -m lib.check` must pass with no errors for every component:
- TOML fields present, units known, `min <= typ <= max`, every param and pin has a cite.
- Symbol pins (number, name, type) match `[[pin]]` exactly; footprint pads cover every pin number.
- Every `calc.EXAMPLES` row reproduces within its tolerance.
- `typ_ref` names a `[[pin]]` and needs `typ`; ordering is not checked for rows with any `*_ref`. `tol_pct` needs
  `typ`, forbids `min`/`max`, and `lo <= hi`.
- Families: see "Families and variants". Series components: see "Series components" and "Capacitor series".

The generated README has a "Limits of this data" line for every part: row counts per scope (25C-only rows hold only
at 25 degC), curve rows, text rows, and, when a junction-temperature row (unit degC, `abs_max`/`rec_op`, "TJ" or
"junction" in symbol or name) exists with no `check_ambient` row, a reminder that temperatures are TJ and that
TJ = TA + P x RthJA.

`python3 -m unittest discover -s tests` must pass.
